# Research record: sportswear design platform

Date: 2026-09-27. Status: input to `plans/sportswear-design-platform.md`.
Method: four parallel read-only investigations (kitwright audit, Sportswear audit,
competitor study, open-source survey). No product code was written.

Evidence labels used below: **C** confirmed on the vendor's own page, **claimed** stated
only in vendor blog posts or marketing, **NF** not found. Competitor pages were read
through a summarising fetch tool, so short quotes are indicative, not verbatim-checked.
No independent reviews were found for either competitor.

Positioning summary. specform turns a reference image into an editable tech pack and
stops there: no patterns, no DXF, no nesting, no costing. fashionINSTA outputs pattern
geometry but is built around a brand's existing archive of 100+ DXF patterns, weeks of
training and enterprise pricing. Neither visibly serves a non-expert going from plain text
to graded sportswear patterns plus a tech pack.

Practice worth matching (in our own words and design): specform's per-field status of
assumed, suggested, needs input, confirmed. It is the same idea as the v1 criterion that
assumptions are never shown as verified.

## 2. Open-source decisions

| Need | Decision | Choice | Licence | Custom code that remains |
|---|---|---|---|---|
| Geometry kernel for drafting | Extend | `@freesewing/core` (npm 4.10.2, active) | MIT | All knit block formulas, stretch-to-ease model, polo and jersey designs |
| DXF writing | Build on existing | Extend `lib/pattern/dxf.ts` in TypeScript | own | AAMA/ASTM layer map, piece blocks, `.rul` grade table |
| DXF independent check | Adopt | `ezdxf` (PyPI 1.4.4) as a reader in tests | MIT | Round-trip assertions |
| Pattern PDF | Adopt | `pdfkit` | MIT | Tiling, 1:1 scale check square |
| Nesting | Adopt | `spyrrow` (PyPI 0.9.0), Python binding to `sparrow` | MIT, links `jagua-rs` under MPL-2.0 | Curve flattening, pair and mirror rules, size-ratio markers, consumption maths |
| Geometry helpers | Adopt | `shapely` | BSD-3 | none |
| Grading | Build | Re-draft per size, difference the grade points | own | All of it |
| Size charts | Build | Own or customer-supplied chart | own | All of it |
| Tech pack schema | Build | none suitable found | own | All of it |

Rejected on licence: Seamly2D, Valentina, JBlockCreator, Packaide (all GPL-3.0),
libnest2d and pynest2d (LGPL-3.0, and weak on concave shapes), Deepnest and Patro (no
licence declared). GarmentCode (MIT, Python) is a useful reference for piece topology but
targets 3D simulation datasets.

Findings that limit what can be reused:
- FreeSewing's tee design has no stretch option and uses positive ease. It has no polo or
  jersey. Its stretch helper is `1 / (1 + stretch)`. No open design derives ease from
  measured stretch and recovery.
- No permissively licensed library emits AAMA/ASTM garment DXF with grade rules. No open
  validator or sample file set was found. Validation means importing into a CAD system.
- No authoritative open source for knit negative-ease rules was found, only sewing-blog
  rules of thumb. These formulas need review by a pattern maker.

Not verified: spyrrow solution quality and runtime on real markers, ANSUR II licence
terms, FreeSewing's PDF tiling approach, MPL-2.0 acceptability (needs a legal view).
GitHub code search was not run (the CLI lost its login mid-survey), so "nothing exists"
rests on repository and web search.

## 3. Gap list: the current POC against the references and the v1 criteria

Severity: **A** blocks a v1 acceptance criterion, **B** needed for v1 quality, **C** hygiene.

### Pattern correctness
1. **A** Sleeve cap does not match the armhole. Recomputed for default size M: cap 28.6 cm
   against armhole 32.5 cm. Pattern side seam 52.4 cm against published 50.2 cm. These
   figures come from a scratch recomputation of the formulas in `lib/pattern/draft.ts`,
   not from a repo test. Reproduce them as failing tests first.
2. **A** No seam-length validation in either codebase.
3. **A** The piece set is the same for every style. Style reaches the draft only through
   measurement deltas. Raglan is drafted as set-in. Polo and henley get no collar or
   placket. No neckband, cuff or hem band pieces.
4. **A** No stretch or negative ease. Knit tees reuse woven proportions.
5. **A** Seam allowance is a note, not geometry. No notches, drill holes or internal lines.
6. **A** Grading: S/M/L only, armhole depth and neck drops do not grade. The writer can
   emit any size, but the export button offers size M only.
7. **B** Front and back differ only in neck drop. Curves are single quadratic Beziers
   sampled to 8 segments and rounded to 1 mm. Sleeve piece y-axis is inverted.
8. **A** DXF is plain geometry. No blocks, no AAMA layers, no grade table. No pattern PDF.

### Measurement truthfulness
9. **A** Six of ten points of measure are back-computed from the pixels of the hand-drawn
   flat (`lib/garment/calibration.ts`). The tech pack labels every row the same way.
10. **A** No per-measurement provenance field. Created packs can never reach "verified",
    and "production ready" keys off provenance rather than review state.
11. **B** The flat is anisotropic (4.5 px/cm vertical, 1.741 horizontal) and not to scale,
    yet it is the reference image for renders.

### Intent layer
12. **A** The model never receives the current spec. Request body is messages only.
13. **A** Invalid model actions are dropped silently.
14. **A** No clarifying questions. No measurement actions in the vocabulary.
15. **B** No tool-result round trip, so the explanatory sentence is often missing.
16. **B** Type and schema drift on colour values. Render route casts unvalidated strings.
17. **B** `GarmentSpec` is a TypeScript interface, not a schema, so there is nothing to
    share with Python.

### Tech pack
18. **A** No bill of materials. No server-side PDF (browser print only).
19. **B** No colourway sheet, artwork placement sheet, labels or packaging, version history.
20. **A** Sportswear's tech pack is a vision model reading an AI-generated image, unvalidated
    and unconnected to the pattern. It cannot meet "changing a measurement updates the
    flat, the table and the pattern together".

### Marker, fabric, costing
21. **B** Nester is a greedy bottom-left fill. It tests real polygon intersections, but
    starting positions come from bounding boxes, so pieces do not settle into concave
    gaps. 52-61% efficiency against an industry 80-88%. Single size only.
22. **B** `on_fold` is parsed and ignored, so fold pieces under-consume fabric. Seam
    allowance may be double-counted.
23. **B** Two costing implementations; the one in use is untested. "Margin" is a markup.
    No wastage, no currency type. Rates are assumptions.
24. **B** Cache keyed on file existence, so a price change returns the old cost.
25. **B** DXF reader is hand-rolled, ASCII only, and its layer map (grain 5, notches 7)
    does not match the usual AAMA map (grain 7, notches 4). No sample DXF exists anywhere
    in the platform folder, so this is unverified.

### Platform
26. **A** No database, no accounts, no tenancy. Both paid API routes are unauthenticated
    and have no rate limit.
27. **B** Sportswear is not service-ready: module globals, errors swallowed with exit code
    0, unsanitised SKU in paths, `.env` file required, unpinned dependencies, no lock file.
28. **B** Sportswear has no sample data, so about 9 of 28 tests cannot pass as committed.
29. **C** kitwright cannot build until `pnpm install` is re-run (symlinks point at the old
    folder location).
30. **C** README claims in both repos are stale ("static export", "no real AI"; "AAMA/ASTM
    compliance is verified" with no code behind it).
31. **C** Possible licence problem: the SegFormer clothes segmentation weights may derive
    from non-commercial NVIDIA weights. Unverified.
32. **C** Name drift between "Kitwright" and "Knitwright".

## 4. What survives from each codebase

kitwright, kept: the style registry and measurement derivation, the action vocabulary,
schema validation and stream parser, the offline parser, project store interface, render
route, tech pack document model, tolerance maths, and the 44 unit and 21 e2e test files.
Replaced with reason: `lib/pattern/draft.ts` formulas (gaps 1, 3, 4) and pixel calibration
as a measurement source (gap 9). Its tests stay as regression inputs.

Sportswear, kept: fabric model (nap, weight, cost per kg or per metre), logo compositing,
pipeline step structure, the 28 tests once sample data exists. Replaced with reason: the
nester (gap 21), the hand-rolled DXF reader (gap 25, replaced by a JSON contract), the
vision tech pack (gap 20), shrinkage scaling location (moved so that the exported pattern
and the marker agree). Plainly stated: less of Sportswear carries forward than of
kitwright.

fashionINSTA is already absent from runtime code. It appears only in comments, the README
and a diagram label.

## 5. Corrections after adversarial review

The blueprint review spot-checked 17 claims against source. Three were corrected above:
the draft does receive style through measurement deltas (only the piece set is fixed),
the DXF writer can emit any size (the limit is in the export button), and the nester does
test polygon intersections. Sportswear is 1,402 lines of Python including tests, not
1,620, and pins no Python version.
